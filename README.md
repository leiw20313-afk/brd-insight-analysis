BRD 场景洞察技能介绍
大家好，今天介绍一个能帮我们梳理业务需求的技能，`brd-insight-analysis`。

它可以把 BRD、会议纪要等材料，整理成业务容易看懂、也方便逐项确认的用户故事和使用场景。通常可以在正式写 PRD 前使用，先请业务确认我们对用户、任务和流程的理解有没有偏差。
它能帮上什么忙
拿到材料后，技能会整理出材料中明确的目标、用户角色、用户要完成的任务、相关规则和范围，再用用户视角写出对应场景。报告里还会列出与这些场景有关、可能存在风险的遗漏，以及确实需要业务决定的问题。

这样一来，团队讨论时能更快分清楚三件事，材料已经说清了什么，哪些地方还需要业务拍板，确认后的需求又该如何落到功能和验收标准上。
它怎么工作
整个过程分两步。

**第一步是请业务确认场景。**报告先归纳材料里已经明确的内容，再按角色整理用户故事，并逐条还原对应的使用场景。材料没有说明的地方不会自行补全；只有当缺失、含糊或冲突会影响需求判断时，才会提出问题。业务也可以对每条故事回复准确或需要修改。

**第二步是整理产品确认版。**等必要问题有了答复、相关场景也决定是否纳入后，产品再整理用户故事、验收标准和功能清单，并标明它们之间的对应关系。这一版可以作为后续编写 PRD 的需求基线。

技能以团队提交的材料为依据，不会替业务确认需求，也不负责核验材料真实性或审查经营测算。报告会生成离线 HTML 文件，方便搜索、筛选、打印和另存为 PDF。
怎么开始用
在 Codex 里调用 [$brd-insight-analysis](D:\\wanglei1652\\Documents\\ChatGPT\\New project\\.agents\\skills\\brd-insight-analysis\\SKILL.md)，附上 BRD、会议纪要或相关规则材料，并说明要做业务场景确认还是整理产品确认版。

可以这样下指令：
请使用 $brd-insight-analysis 分析我提供的 BRD 和会议纪要，先生成业务场景确认稿。

请把材料已明确的内容、需要业务决定的事项和候选补充场景分开写。用户故事按角色整理，场景与故事逐条对应。材料没有说明的内容不要推测，已经写清的范围、验收和优先级不要重复提问。

请将报告输出为离线 HTML，保存到指定目录。
业务反馈回来后，再把反馈和原材料一起提供，请技能更新需修改的故事和场景。必要决定完成后，就可以继续整理产品确认版。报告会按版本保留，不覆盖之前的报告或原始材料。
建议怎么在团队里用
可以把它放在需求进入 PRD 之前。产品先用现有材料生成场景确认稿，业务逐条确认并补充必要信息，产品再根据确认结果整理 PRD 基线。

这样做能让需求交接更清楚，也方便团队回头查看某项功能对应的业务场景和验收要求。业务仍然负责确认业务决定，产品经理负责把确认结果整理成可执行的需求。
