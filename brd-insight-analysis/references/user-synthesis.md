# 核心用户与关键需求判断

仅在核心场景中使用，核心结果可在一页纸和故事中简述，不另做画像或动因报告。

- **首期用户：**用“谁 + 什么情境/行为 + 为什么先服务”说明。优先依据已知的受阻、替代做法、主动求助或试点选择。材料不足时标“待确认”，不编造频率、规模或购买力。
- **关键需求：**把指定功能与用户要取得的结果分开；用“在……时，需要……，才能……”表达。对比当前替代做法和用户放弃/改选/购买（内部产品则采用/绕开）的条件。没有实际经历时，不把推测写成购买或采用事实。
- **确认取舍：**业务决定首期范围与承诺；产品解释不是购买事实。对外用具体问题和确认标准表达分歧，不显示责任方标签。
- **价值表达：**用“具体处境 → 阻碍 → 可兑现结果”写一句即可；不是用户原话，不加引号，不承诺未确认的效果。
- **表达节制：**每个场景保留理解与决定所必需的信息；共享规则用编号引用，不在每个故事重复全文。缺少但不影响本期决定的细节省略。
