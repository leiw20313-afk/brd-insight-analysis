# BRD Insight Analysis Skill

将业务提交的 BRD、会议纪要等材料整理为业务易读、便于确认的用户故事和场景，减少需求误读、场景漏项与未经确认的推断。主流程见 `SKILL.md`；输出规则见 `references/report-contract.md`。

## 业务场景确认阶段

报告顺序：

1. **一页纸结论：只放材料明确/业务此前已确认的内容。**需业务回答的事项另列，不混入结论。
2. **用户故事概览：**按角色分组，“序号｜角色｜动作/能力｜价值”。
3. **场景故事链 / 目标旅程：**以用户视角进入，按同序号和角色呼应故事概览；简短展示触发、任务、材料明确步骤/规则和结果。
4. **需业务判断的补充场景：**只列与明确故事相关、若不考虑有具体风险的候选，请业务决定是否纳入。
5. **需要业务回答的问题：**必须答复优先、建议答复随后；业务逐条确认场景还原是否准确，再回答材料缺失、含糊、冲突且会影响场景决定的事项。

不展示材料清单、独立角色/画像、种子用户、购买动因或真实问题链模块。产品不额外核验业务材料真实性，也不检查经营测算、成本、ROI。材料明确的范围、业务可判断的验收和优先级直接整理，不重复询问。

## 产品最终确认阶段

必要业务决定与候选场景取舍完成后，输出可直接用于 PRD 的确认版：用户故事表“序号｜角色｜动作/能力｜价值｜验收标准”；功能清单写方案要点、故事映射和验收结果，按“关键／重要／一般”分组。最终版不得留待确认问题。

## 页面要求

输出单文件离线 HTML，层级清楚、句子短、故事和场景逐项对应。提供目录跳转、搜索、按角色/功能优先级筛选、展开/收起、打印/另存 PDF、返回顶部；键盘和读屏可用，适配窄屏与打印。交互不隐藏内容状态，也不代替业务答复。

## 验收检查

使用脱敏 BRD/会议纪要至少检查信息清晰、角色多、材料缺字段、故事边界、候选风险场景、含糊/冲突/完整确认等情形：

- 一页纸只有材料明确或业务此前确认的信息；所有需业务答复内容单独呈现。故事场景需由业务逐条确认准确/需修改，但不要求业务重新证明材料真伪。
- 不出现“材料清单、种子用户、真实动因/问题链”等独立章节；角色只在故事概览和场景中出现。
- 故事概览与场景详情序号、角色、动作、价值一一对应；场景从用户视角讲述，文字精简但不漏关键步骤、规则和结果；每条故事都提供“准确/需修改”的业务回复位。
- 范围、验收、优先级若已写明就直接提取；不重复要求业务确认。只有缺失、含糊、冲突且影响决定才提问。
- 产品不验证业务材料的真实性，不核对经营测算/成本/ROI，不自行补造当前做法或流程。
- 补充候选场景必须关联已有故事，说明若不纳入可能造成的风险，并由业务决定纳入或排除。
- 最终用户故事表含角色、动作/能力、价值和业务可判断的验收标准；功能清单有解决方案要点、故事映射、验收结果和关键/重要/一般分组。
- 页面交互、键盘操作、窄屏阅读、打印和离线可用；本地 Markdown 链接有效，无外部依赖。
