# 业务需求洞察

[技能入口](SKILL.md)｜[报告契约](references/report-contract.md)

用五步让业务核对场景原意；不同章节可为便于阅读适度重提信息，保持术语准确、简洁一致：一页纸结论 → 用户故事概览 → 场景故事链 → 风险遗漏场景 → 待确认事项与确认记录。场景按业务发生顺序阅读，并以主流程、分支流程、异常流程等标签标识类型；详情可展开。业务回复事项编号及具体决定，每轮都保留结果和状态；待确认问题及页面规则问题在所属场景内用红色折叠区展示，默认收起；自由文案限制、枚举值/数量等按场景确认。状态只有“未确认 / 已确认”，未全部明确时保持“未确认”。报告内交叉引用均可点击直达。

文档使用简洁、专业的中文；用分层标题、表格、流程步骤和状态标记帮助阅读，不为避免重复而牺牲理解。最终版及已确认事项不展示“为什么要确认”和“确认标准”。最终版只含已确认的完整正文，没有确认过程或内容引用超链；提供“复制确认基线”按钮，复制范围为完整正文（不含工具栏、导航、页眉元数据或页脚）；无脚本时正文仍完整展开。两阶段均生成离线中文 HTML，版本独立递增。

## 回归用例

- 按业务目标/价值逐项映射用户结果和故事；未覆盖的结果形成有目标锚点的“待业务确认”候选，不能写成既定事实。
- 只有功能提案：保留现状、阻点栏并说明未知，不虚构真实经历。
- 同一任务有主、分支、异常三种走法：概览一行，每个场景按业务发生顺序排列并加类型标签，按场景指出哪一步是否符合原意。
- 客户要求修改异常处理：未完整明确前保持“未确认”；修改点和已回答部分记入历史，全部明确并获答复后才变为“已确认”。
- 发现高相关新条件：命名为风险遗漏场景，优先写若不考虑的风险，再按场景结构展示。纳入则补规则与验收；暂不考虑则保留范围决定，不生成本期需求。
